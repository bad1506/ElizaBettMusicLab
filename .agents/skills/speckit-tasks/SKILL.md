# Tasks

Read the active constitution, specification, and plan.

Create `tasks.md` with small dependency-ordered tasks. Each task should name the target file/component, describe the behavior change, and identify its validation target. Group tasks by logical area such as contracts, backend, frontend, tests, infrastructure, and documentation.

Include security and regression tasks whenever auth, user input, storage, external integrations, or sensitive data are affected. Do not create tasks for work outside the approved scope.
